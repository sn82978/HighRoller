# Pre-refactor Q-learning metrics — kept for provenance, not for citing

These four CSVs are the source of every Q-learning number in the progress
report (Section 4.2, Figures 3–5). They are archived here rather than deleted
because the report cites them, so they need to stay identifiable — but **none
of them can be regenerated by the current code, and none of them are comparable
to the other models.**

| file | rows |
|---|---|
| `0.7T_0.2E_qtable_training.csv` | 35 |
| `0.7T_0.2E_qtable_eval.csv` | 35 |
| `0.8T_0.2E_qtable_training.csv` | 30 |
| `0.8T_0.2E_qtable_eval.csv` | 30 |

## Why they can't be reproduced

**The two "configurations" never existed in the code.** The report describes a
70/20 and an 80/20 train/evaluation split. `data_preparation.py` reads the
canonical 70/15/15 temporal split from `BaselineModels.data_loader`, and takes
no split-ratio argument; `"0.8T_0.2E"` was only ever a filename prefix. The
ratios came from `split_data.py`, which partitions **day-files at random** —
the non-temporal split the proposal specifically rules out — and which is marked
SUPERSEDED. That split is also not portable: it shuffles the output of
`os.listdir()`, so `random.seed(42)` does not reproduce it across machines.

**The runs were not seeded.** Exploration, tie-breaking and episode sampling all
drew from the unseeded global `np.random`, so the 30-run spread is not
reproducible even on the same machine.

**The environment they ran in has since been corrected.** Those runs filled at
the same candle close the state was read from (lookahead), applied no slippage,
and computed fee drag against a `max(0, ...)`-clamped gross PnL that discarded
losing steps while keeping their fees — the 21.5× discrepancy the report flags
in §3.3.

**The row counts disagree with the report.** It says 30 runs per configuration;
the 70/20 files hold 35.

## Schema

They carry the old `score()` output — `win_rate`, `pnl_per_1k_capital`,
`turnover`, `avg_holding_period`, `fee_fraction_gross_pnl`, `env_name`. The
current scorer (`sim/metrics.py`) emits none of those names, so these files
cannot be concatenated with anything produced today.

## What replaces them

`python QLearning/training.py` writes `QLearning/metrics/qlearning_{train,val}.csv`:
30 seeded runs on the canonical temporal split, through the shared cost model,
scored by the same function as every other model in the repo.
