### Fee-fraction denominator check

```
                                   no_trade  buy_and_hold  xgboost_theta_0.01
total_fills                             0.0   1343.000000         1343.000000
net_gross                               0.0   2802.846268         -485.192051
positive_only_gross                     0.0  60202.846268        59914.807949
fee_frac_net_gross (as coded)           NaN      1.472671                 NaN
fee_frac_positive_only (RL style)       NaN      0.068563            0.070090
```

`fee_frac_net_gross` divides by realised PnL with fees added back, losing markets contributing their actual negative PnL, and is NaN when that is <= 0. The positive-only convention drops every loss from the denominator while its fees stay in the numerator, so it reads best exactly when a policy is doing worst. Both are shown so the gap is visible; the paper must pick one for all models or the comparison means nothing.

## Test-split confirmation

`load_split('test', ...)` was not called in this run; the reported split is `val`.

One caveat, stated rather than buried: `market_universe()` reads `event_slug`, `start_ts`, `winner` and `truncated` from all daily files in order to compute the split boundaries, so test-period *labels* are read into memory by the bounds calculation. They never reach features, fitting, threshold selection, or any reported metric -- the test row above shows dates and counts only -- but "the test bytes were never touched" would be false.
